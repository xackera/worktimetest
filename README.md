# Учёт рабочего времени

Небольшое веб-приложение: сотрудники, таймер с описанием задачи, отчёт по записям и общему времени за период. Все данные хранятся в PostgreSQL и переживают перезапуск.

**Стек:** ASP.NET Core 8 (Minimal API), Dapper и обычный SQL, PostgreSQL 16, миграции через DbUp, статическая страница на чистом JS, тесты на xUnit и Testcontainers.

## Запуск

Нужен Docker. Приложение и база запускаются одной командой:

```bash
docker compose up --build
```

Приложение откроется на http://localhost:8080. SQL-миграции применяются автоматически при старте.

Для разработки базу можно запустить в Docker, а приложение из исходников (нужен .NET SDK 8 или новее):

```bash
docker compose up -d db
```

```bash
dotnet run --project src/WorkTime.Web
```

В этом случае адрес — http://localhost:5045. База доступна на порту 5433, чтобы не конфликтовать с локальным PostgreSQL. Строка подключения задана в `appsettings.json` и переопределяется переменной `ConnectionStrings__Default`. Пароль в ней нужен только для локальной базы из `docker-compose.yml`.

Удалить все данные:

```bash
docker compose down -v
```

### Решения, которые стоит пояснить

- **Dapper и обычный SQL вместо ORM.** Таблиц две, запросов мало, а важные правила удобнее выразить прямо в SQL. Первая версия была на EF Core, и переход убрал обработку исключений при гонках (см. ниже). Цена — SQL проверяется не компилятором, а только тестами на настоящей базе.
- **Один таймер на сотрудника гарантирует база.** Частичный уникальный индекс `ux_time_entries_one_running` по условию `ended_at IS NULL` не даст записать второй идущий таймер никому, даже в обход приложения.
- **Старт и стоп — один атомарный запрос.** Старт — это `INSERT ... ON CONFLICT DO NOTHING`, стоп — `UPDATE ... WHERE ended_at IS NULL`. Сначала выполняется запись, а если строка не вернулась, отдельный запрос выясняет причину для ответа 404 или 409. Окна между проверкой и записью нет, поэтому гонку не нужно ловить через исключения.
- **Границы периода — это моменты времени, а не даты.** Где начинаются сутки, знает только браузер, потому что сервер не знает часовой пояс пользователя. Браузер сам считает локальную полночь, поэтому корректно обрабатываются и сутки на 23 или 25 часов.
- **В отчёт идёт только пересечение записи с периодом.** Запись с 23:00 до 02:00 даёт час одному дню и два часа следующему. Идущий таймер считается до текущего момента.
- **Время хранится с точностью до секунды.** Так сумма записей точно совпадает с итогом, и потери от округления не накапливаются.
- **Счётчик в браузере начинается со значения от сервера.** Неточные часы компьютера не исказят показания.
- **Часы в коде подменяемые.** `TimeProvider` позволяет тестам управлять временем без пауз и случайных падений.

### Что намеренно не сделано

Редактирование и удаление записей, авторизация и экспорт: задание их не требует. Сотрудники с одинаковыми именами разрешены, потому что однофамильцы реальны.

### Найденные и исправленные ошибки

Все ошибки были в коде, который написал ИИ. Ошибки, связанные с базой, относятся к разным версиям: сначала приложение было на EF Core, затем его перевели на Dapper.

| Ошибка | Как нашли | Исправление |
|---|---|---|
| Символ `\u0000` в имени или описании давал ответ 500: PostgreSQL не хранит NUL в тексте | запрос через `curl` с необычными данными | проверка ввода, ответ 400, регрессионные тесты |
| После успешного «Стоп» появлялась ложная ошибка, а в отчёте оставалась строка «идёт», если в форме уже был введён другой период | сценарий в браузере | обновляется показанный отчёт, а не текущие поля формы |
| Под отчётом без идущих таймеров выводился текст `null`: `replaceChildren` превращает `null` в строку | скриншот и ревью | элемент добавляется только при необходимости |
| На телефоне страница растягивалась до 636 пикселей при ширине экрана 375 | проверка на мобильной ширине | `grid-template-columns: minmax(0, 1fr)` |
| Поздний ответ старого запроса перезаписывал более новый отчёт. Форма показывала один период, а таблица другой | ревью | учитывается только ответ на последний запрос, в отчёте показан период. Исправление проверено искусственной задержкой ответа |
| Итоги занижались: длительность каждой записи округлялась вниз, поэтому 10 записей по 1,9 с давали 10 с вместо 19 | ревью | время хранится с точностью до секунды, добавлен тест |
| Новая порция ввода терялась: перерисовка списка сбрасывала фокус поля, где печатает пользователь | ревью | фокус и позиция курсора восстанавливаются |
| Счётчик таймера мог отстать после сна компьютера, а данные — устареть после изменений в другой вкладке | ревью | `Date.now` вместо `performance.now`, обновление при возврате на вкладку |
| При первом запуске compose база могла считаться готовой слишком рано, а приложение не перезапускалось после сбоя | ревью | `pg_isready -h 127.0.0.1` и `restart: unless-stopped` |
| Заголовок `Location` вёл на несуществующий маршрут, порт базы был открыт на всех интерфейсах | ревью | заголовок убран, порты привязаны к `127.0.0.1` |
| Версия на EF Core: конфликт EF Core 8.0.11 и 8.0.33 из-за плавающих версий `8.0.*` (предупреждение `MSB3277`) | предупреждение сборки | точные версии пакетов, позже EF Core убран совсем |
| Версия на Dapper: SQL-миграция не попадала в сборку из-за неверного пути в `.csproj`. DbUp молча сообщал об успехе, а таблицы не создавались | упало большинство тестов | исправлен путь |
| Версия на Dapper: последняя `dbup-postgresql` требует Npgsql 10 и конфликтовала с Npgsql 8 (`NU1605`) | ошибка восстановления пакетов | выбран `dbup-postgresql` 5.0.40, совместимый с Npgsql 8 |
| Уязвимые транзитивные пакеты в тестовом проекте (`System.Net.Http` 4.3.0, `System.Text.RegularExpressions` 4.3.0) | `dotnet list package --vulnerable` | обновлены xUnit и тестовый SDK |
| Версия на EF Core: **тесты на гонки ничего не доказывали.** С отключённой защитой параллельные запросы всё равно проходили | мутационная проверка | детерминированные тесты, а после перехода на атомарный SQL окно гонки исчезло совсем |

### Как проверялись сами тесты

Первый набор тестов прошёл с первого запуска, что само по себе ничего не доказывает. Поэтому код намеренно ломали в отдельной копии репозитория и смотрели, упадут ли тесты.

На версии с EF Core это дало важный результат: при отключённой защите от гонок тесты оставались зелёными, потому что параллельные запросы почти не попадали в короткое окно между проверкой и записью. После перехода на атомарный SQL этого окна больше нет.

Результат на текущей версии — все поломки пойманы:

| Намеренная поломка | Какой тест её поймал |
|---|---|
| Старт без `ON CONFLICT` | `Second_start_is_rejected_and_keeps_running_timer_untouched` |
| Стоп без условия `ended_at IS NULL` | `Second_stop_is_rejected_and_keeps_first_end_time` |
| Индекс не уникальный | `Database_itself_forbids_second_running_timer` |
| Нет обрезки записи по концу периода | `Entry_crossing_period_boundary_counts_only_its_part_in_period` |
| Нет приведения границ периода к UTC | `Period_boundaries_with_non_utc_offset_are_respected` |
| Запись, закончившаяся в момент начала периода, попадает в отчёт | `Entry_ending_exactly_at_period_start_is_not_included` |
| Запись, начавшаяся в момент конца периода, попадает в отчёт | `Entry_starting_exactly_at_period_end_is_not_included` |
| Идущий таймер показан в будущем периоде | `Running_timer_is_not_included_in_future_period` |
| Нет проверки `to <= from` | `Period_with_end_not_after_start_is_rejected` |
| Время хранится с долями секунды | `Fractions_of_second_do_not_accumulate_into_lost_time` |
| Завершённые записи показаны как идущие | `Stopped_timer_is_no_longer_shown_as_running` |
| Фильтр по сотруднику не работает | `Filter_returns_only_selected_employee` |

### Находки ревью, которые не исправлялись

- Нет автотестов на интерфейс. Для объёма этого задания достаточно ручной проверки, но первым следующим шагом были бы браузерные тесты.
- Нет периодического опроса сервера: другая вкладка видит изменения при возврате на неё или при следующем действии, этого достаточно для простого интерфейса.

Сборка под .NET 8 проверена в образе `mcr.microsoft.com/dotnet/sdk:8.0`. Локально разработка шла на SDK 9 с целевой платформой `net8.0` и рантаймом 8.
